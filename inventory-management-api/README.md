# Inventory Management REST API

A Node.js, Express, MongoDB and Mongoose REST API for an Inventory and Data Management System.

## 1. Requirements

- Node.js 18 or newer
- npm
- MongoDB Atlas account (recommended for deployment)
- Postman or another API client

## 2. Install and run locally

```bash
npm install
```

Create a `.env` file in the same directory as `server.js`:

```env
PORT=5000
MONGO_URI=mongodb+srv://<username>:<password>@<cluster-host>/inventoryDB?retryWrites=true&w=majority
```

Replace the placeholders with your Atlas database credentials and cluster hostname. Do not upload `.env` to GitHub.

Run:

```bash
npm start
```

The API runs at `http://localhost:5000`.

## 3. Render deployment

1. Push this project to a GitHub repository.
2. In Render, create a **Web Service** and connect that repository.
3. Set the Root Directory to the folder containing `package.json` and `server.js` (leave blank if they are in the repository root).
4. Build Command: `npm install`
5. Start Command: `npm start`
6. In Render → Environment, add:
   - `MONGO_URI` = your complete MongoDB Atlas connection string, including `/inventoryDB`
   - `NODE_ENV` = `production`
7. Save and deploy. Render provides the public `onrender.com` URL.

The app listens on `process.env.PORT` and binds to `0.0.0.0`, as required by hosted web services.

## 4. API endpoints

Base URL locally: `http://localhost:5000/api/products`

| Method | Endpoint | Purpose |
|---|---|---|
| POST | `/api/products` | Create a product |
| GET | `/api/products` | List products |
| GET | `/api/products/:id` | Get one product |
| PUT | `/api/products/:id` | Update a product |
| DELETE | `/api/products/:id` | Delete a product |
| PATCH | `/api/products/:id/stock` | Adjust stock |
| GET | `/api/products/low-stock` | List products at/below reorder level |
| GET | `/api/products/summary` | Category-wise inventory aggregation |

## 5. Example request bodies

### Create product — POST `/api/products`

```json
{
  "name": "Wireless Mouse",
  "sku": "WM-1001",
  "category": "Accessories",
  "price": 599,
  "quantity": 25,
  "reorderLevel": 5,
  "supplier": "Tech Supplies"
}
```

### Update product — PUT `/api/products/:id`

Send one or more allowed fields, for example:

```json
{
  "price": 549,
  "quantity": 30
}
```

### Adjust stock — PATCH `/api/products/:id/stock`

Positive `change` adds stock; negative `change` removes stock.

```json
{
  "change": -3
}
```

## 6. Query examples

- Filter: `GET /api/products?category=Accessories`
- Search: `GET /api/products?search=mouse`
- Price range: `GET /api/products?minPrice=100&maxPrice=1000`
- Sort ascending: `GET /api/products?sort=price`
- Sort descending: `GET /api/products?sort=-price`
- Pagination: `GET /api/products?page=2&limit=5`
- Combined: `GET /api/products?category=Accessories&sort=-price&page=1&limit=10`

## 7. Product fields

- `name`: required product name
- `sku`: required unique stock-keeping unit
- `category`: required category
- `price`: required non-negative number
- `quantity`: required non-negative integer
- `reorderLevel`: non-negative integer; defaults to 10
- `supplier`: supplier name; defaults to `Not specified`
- `stockValue`: virtual field calculated as `price × quantity`

## 8. Notes

- `node_modules` is generated by `npm install`; it should not be committed.
- `.env` contains secrets and is ignored by Git.
- The root route `/` returns a health message. `/api/products` is the product API.
